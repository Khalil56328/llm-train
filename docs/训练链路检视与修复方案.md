# 训练链路检视与修复方案

> 检视范围：`创建训练任务 → 运行 → 生成模型 → 部署 → 访问` 全链路（后端 + 前端）
> 检视日期：2026-08-20

---

## 一、链路全景图（现状）

```
前端(向导创建) → POST /train-tasks           [TrainService.create_task, 仅建 pending 记录]
                 → POST /train-tasks/{id}/submit  [状态→running, dispatch_task("train")]
                                                    │
              dispatch_task: Celery worker 存活? ── yes → 投递队列
                              └─ no → 本地 asyncio 后台执行
                                                    ▼
                           executor.run_training
                            ├─ mock: _run_mock_training(模拟 loss/lr/进度)
                            └─ real: _run_real_training(真实 swift 子进程)
                                                    ▼
                         _create_output_model(建 Model 主记录, 指向目录字符串)
                                                    ▼
前端列表/详情页 → 3s 轮询 logs + metrics (GET /train-tasks/{id}/logs|metrics)
                                                    ▼
前端创建部署 → POST /deployments  → POST /deployments/{id}/start → dispatch_task("inference")
                                                    ▼
                           executor.run_inference
                            ├─ mock: 仅把 status→running、endpoint 写成字符串, 不拉起进程
                            └─ real: subprocess.Popen(vllm/swift 进程)
                                                    ▼
前端在线测试 → POST /deployments/{id}/test  → HTTP 请求 {endpoint}/chat/completions
```

**总体结论**：
- **创建训练、运行训练、日志/指标展示、生成模型记录、部署创建/启动、端点展示** 均已闭环（mock 模式下可跑通）。
- **真正"访问模型"环节是残缺的**：mock 模式部署是"假启动"（不拉起任何服务），`/test` 在线测试必然 502。真实在线推理/对话体验无落地。
- 全链路无 WebSocket（前端用 3s HTTP 轮询），`app/ws/train.py` 的 WS 已实现但前端未接入。

## 二、现有代码逻辑缺陷（按严重度排序）

### 🔴 P0-1 mock 模式部署是"假启动"，在线访问必然失败
**位置**：`backend/app/tasks/executor.py::run_inference`
**问题**：mock 分支只执行 `dep.status = "running"; dep.progress = 100; dep.endpoint = "http://0.0.0.0:{port}/v1"`，**端口上没有任何服务在监听**。前端 `test_deployment` 会用 urllib 请求 `http://0.0.0.0:{port}/v1/chat/completions`，必然连接失败返回 502。这是"部署→访问"环节最大的缺口。

### 🔴 P0-2 训练产物模型未落真实权重文件，且缺 ModelVersion/ModelFile
**位置**：`backend/app/tasks/executor.py::_create_output_model`
**问题**：
1. mock 模式 `_run_mock_training` **完全不落盘**，`storage/models/{task_id}` 目录是空的（甚至不存在）。
2. 即使 real 模式 swift 写入了权重，`_create_output_model` 只 `session.add(Model(...))` 一条主记录，**不创建 ModelVersion / ModelFile 子记录**，与 `model_service.import_model`（会复制版本+文件）不一致。
3. `Model.storage_path` 仅指向目录字符串，部署该模型时目录可能为空 → 推理无权重可加载。

### 🟠 P1-3 `build_export_command` 定义了但从未被调用
**位置**：`backend/app/engine/swift/adapter.py`；`executor.py::run_training`
**问题**：压缩/导出类任务（`task_type=compression`）在 `run_training` 中和微调走同一套训练执行逻辑，**没有单独的导出执行路径**。`build_export_command` 无任何调用方，压缩类任务的"导出产物"环节未接入执行链。

### 🟠 P1-4 `DeployInstance`（POD）状态从不更新
**位置**：`backend/app/services/deploy_service.py::create_deployment`、`executor.py::run_inference`
**问题**：创建部署时生成 `status="pending"` 的 POD 实例，但 `run_inference` 启动后**从不把实例更新为 running/ready**，也不回填 host_ip/pod_ip。前端展示的 POD 永远是 pending。

### 🟠 P1-5 无独立在线推理端点；`test_deployment` 非流式、绑定 0.0.0.0
**位置**：`backend/app/api/v1/deployments.py::test_deployment`
**问题**：
1. 后端无独立的 OpenAI 兼容开放端点，唯一入口是 `/deployments/{id}/test` 代理。
2. 该代理是单轮非流式（无 SSE），且 `endpoint` 绑定 `0.0.0.0`（容器内），外部客户端无法直连，只能经后端代理。
3. 无多轮对话 / 会话管理。

### 🟠 P1-6 真实模式 pause 语义错误
**位置**：`executor.py::_run_real_training`
**问题**：真实训练中收到 pause 信号，代码 `task.status = "paused"` 后 `clear_control(task.id)` 清除信号，但**进程继续运行**，日志注释也写明"将在进程结束后生效"——这并非真正的暂停（无法挂起进程）。P0 级别语义混淆。

### 🟡 P2-7 训练产物"注册模型"前端是 mock
**位置**：`web-ui/src/views/training/TrainTaskDetail.vue::registerModel`
**问题**：`registerModel()` 只 `ElMessage.success('产出模型已存在于模型库')`，未调用任何注册/创建模型 API。"训练→模型入库"这一跳完全依赖后端自动回填 `outputModelId/outputModelName`，前端无手动入库入口，也无法关联训练产物做部署。

### 🟡 P2-8 训练任务状态机定义与代码使用脱节（`stopped`）
**位置**：`web-ui/src/types/index.ts`（`TaskStatus`）、`TrainTaskDetail.vue`、`backend/app/api/v1/training.py`
**问题**：
- 后端 `executor` 取消/停止时写 `status = "stopped"`，`training.py` 的 `SUBMITTABLE_STATUS = ("pending", "failed", "stopped")` 也认可 `stopped`。
- 但前端 `TaskStatus` 类型**没有 `stopped`**（只有 `cancelled`），`TrainTaskDetail.vue` 模板里判断 `task.status === 'stopped'` 显示"重试"却无类型覆盖。
- API 有 `stopTrainTask`（`/stop`）但前端无停止入口，UI 停止链路未闭环。

### 🟡 P2-9 部署详情"日志"区是空占位
**位置**：`web-ui/src/views/service/DeploymentDetail.vue`
**问题**：日志区块 `<el-empty description="暂无日志信息"/>`，后端也没有部署日志接口（`executor.run_inference` 用 `subprocess.DEVNULL` 丢弃了全部日志）。

### 🟡 P2-10 WebSocket 已实现但前端未接入
**位置**：`backend/app/ws/train.py`（已实现）、`web-ui/src/utils/request.ts` / `TrainTaskDetail.vue`
**问题**：WS 实时日志端点已注册且能工作，但前端仍用 3s HTTP 轮询。**丢日志、3s 延迟、额外请求开销**。WS 能力闲置。

### 🟡 P2-11 列表页在接口异常时静默降级为 mock 数据
**位置**：`web-ui/src/views/training/*List.vue` catch 分支
**问题**：接口异常时填充硬编码行数据，会**掩盖后端不可用**，排查时容易误判（以为有数据其实后端挂了）。

### 🟢 P3-12 前端 `datasetName` 显示 undefined 等小瑕疵
**位置**：`TrainTaskDetail.vue`
**问题**：详情 reactive 对象未定义/未回填 `datasetName` 字段，可能导致显示 `undefined`；部署列表"进入容器"按钮无绑定逻辑。

## 三、修复方案

### 方案 1（P0-1/P0-2）：mock 模式提供"内存推理服务"，并落盘产物模型
**思路**：让 mock 模式真正可"访问"，同时让产出模型可被部署加载。

1. **mock 推理服务**：在 `run_inference` mock 分支，启动一个轻量 **HTTP 服务**（内嵌 `aiohttp`/`starlette`），监听 `127.0.0.1:{port}`，实现 OpenAI 兼容的 `/v1/chat/completions`（从请求 messages 拼一段规则化回复即可）。把 `dep.endpoint` 写成 `http://127.0.0.1:{port}/v1`。
   - 这样 `test_deployment` 能真正连通，在线测试闭环。
2. **mock 产物落盘**：`_run_mock_training` 结束时在 `output_dir` 写入一个最小的模型标识文件（如 `config.json` / `weights_mock.txt`），确保部署时 `model_path` 指向的目录非空且真实存在。
3. **补 ModelVersion/ModelFile**：`_create_output_model` 里为产物模型创建一条 `ModelVersion`（默认 v1，`storage_path=output_dir`，`is_default=True`），保持与 `import_model` 一致。

### 方案 2（P1-3）：压缩类任务走导出执行路径
- 在 `run_training` 开头按 `task.task_type` 分支：`compression` → 调用 `SwiftEngineAdapter.build_export_command` 生成命令并执行（复用 `_run_real_training` / 新增 `_run_real_export`）；其余类型走现有训练逻辑。
- 导出成功后同样调用 `_create_output_model` 入库，产物标记为压缩后模型。

### 方案 3（P1-4）：启动后回填 POD 实例状态
- `run_inference` 启动成功后，查询该部署的 `DeployInstance` 列表，逐个更新 `status="running"`、`host_ip/pod_ip`（mock 填 `127.0.0.1`），`ready_at=now`。
- `stop_deployment` 时对应将实例置回 `stopped`。

### 方案 4（P1-5）：补齐独立在线推理端点 + 支持流式
- 新增 `backend/app/api/v1/inference.py`：`POST /api/inference/chat/completions`，入参带 `deployment_id`，转发到对应 endpoint 并支持 `stream=true`（SSE）。
- 前端 `src/views/service/DeploymentDetail.vue` / `DeploymentList.vue` 升级为**流式对话**界面（读 `text/event-stream`），支持多轮。
- 生产环境将 `endpoint` 暴露为外部可访问地址（非 `0.0.0.0` 内部端口），或由 Nginx 直接反代到推理服务端口。

### 方案 5（P1-6）：真实模式 pause 语义修正
- 真实训练暂停需真正挂起进程：Unix 下 `proc.send_signal(SIGSTOP/SIGCONT)`，Windows 下不支持则明确提示"真实模式不支持暂停，已忽略"或降级为"取消"。
- 移除 `clear_control(task.id)`（pause 后应保持信号，resume 时由用户触发 SIGCONT 并 clear）。

### 方案 6（P2-7/P2-8）：打通训练产物入库与状态机一致性
- 前端：把 `registerModel` 改为真实调用后端"将训练产出注册为模型"接口（或直接用已有的 `outputModelId` 跳转模型库并支持"基于此模型创建部署"按钮）。
- 类型：`TaskStatus` 加入 `'stopped'`，统一前后端状态机；前端补"停止"按钮 + `stopTrainTask` 调用，`SUBMITTABLE_STATUS` 与 UI 保持一致。
- 后端 `stop` 端点确保写入 `status="stopped"` 并派发控制信号（`executor._handle_control` 已支持 cancel→stopped）。

### 方案 7（P2-9）：补齐部署日志采集
- `run_inference` real 模式不再 `subprocess.DEVNULL`，改为把 stdout/stderr 写入 `DeployInstance` 或部署日志文件；新增 `GET /deployments/{id}/logs` 接口 + 前端渲染。
- mock 模式可输出模拟启动日志。

### 方案 8（P2-10）：前端接入 WebSocket 实时日志
- `TrainTaskDetail.vue` 用 `WebSocket` 连接 `ws://{host}/api/ws/train/{task_id}` 替换（或降级兜底）3s 轮询；`onUnmounted` 关闭连接。

### 方案 9（P2-11/P3-12）：移除 mock 降级 / 修复小瑕疵
- 移除列表页 catch 分支的硬编码 mock 数据，接口失败时展示真实错误状态。
- 修复 `datasetName` 回填、绑定"进入容器"按钮逻辑。

## 四、优先级建议

| 优先级 | 缺陷 | 说明 |
|---|---|---|
| P0（必须） | mock 假启动 / 产物不落盘 | 不修则在线访问永远失败 |
| P1（重要） | 压缩无导出、POD 不更新、无独立推理端点、pause 语义 | 影响真实/关键路径可用性 |
| P2（建议） | 产物入库 mock、状态机、部署日志、WS 未接入、mock 降级 | 影响体验与可维护性 |
| P3（可选） | 前端小瑕疵 | 低风险打磨 |

**最小闭环修复包（快速见效）**：方案 1（内存 mock 推理 + 产物落盘）→ 方案 3（POD 回填）→ 方案 4（流式对话端点）即可让"训练→部署→访问"真正走通。

### ✅ 真实模式部署增强（用户重点要求）

- **进程句柄管理**：新增 `_REAL_INFERENCE_PROCS` 保存真实推理进程，`stop_inference_service` 会 `terminate/kill` 停止。
- **就绪探测**：新增 `_wait_inference_ready`，真实模式启动进程后轮询 TCP 端口（默认 180s 超时，可配 `INFERENCE_READY_TIMEOUT`），服务未就绪前不标记 running，进程异常退出则置为 failed 并附日志。
- **endpoint 收敛**：mock 与 real 的 endpoint 统一为 `http://127.0.0.1:{port}/v1`，后端代理（`/test`、`/api/inference/*`）可稳定访问；对外暴露由 Nginx/容器编排完成。

### 前端新增/修改文件
- `web-ui/src/api/service.ts`：新增 `getDeploymentLogs`、`chatCompletionsStream`（原生 fetch 读 SSE，逐块回调）。
- `web-ui/src/views/service/DeploymentDetail.vue`：在线测试升级为**多轮流式对话**；日志区展示部署日志。
- `web-ui/src/views/training/TrainTaskDetail.vue`：停止按钮、产物查看/创建部署、WS 实时日志。
- `web-ui/src/types/index.ts`：`TaskStatus` 加入 `stopped`。

### 验证
- 后端：`python` 语法校验、模块导入、mock 推理服务单测、`_forward_sync` 非流式转发、httpx 流式代理均通过。
